# Developer blog: Laravel + Storyblok

A developer blog built with **Laravel, Blade and Bootstrap 5**, with **Storyblok** as the CMS. It is dark by default, has
a light theme, and runs entirely on typed content classes generated by
[`tuxonice/storyblok-transfers`](https://github.com/tuxonice/storyblok-transfers).

It is also the first real consumer of that package, so the repo doubles as a field report: every awkward spot is
written down in [`FRICTION.md`](FRICTION.md) with a suggested change to the package.

**What it does**

- Home, post, category, about and category-index pages, read from Storyblok with relations (author, categories).
- Richtext with embedded blocks (code, callout, pull quote, figure), heading anchors and an "on this page" index.
- Server-side syntax highlighting for both themes, reading time, RSS feed, sitemap and `robots.txt`.
- SEO: meta description, canonical URLs, Open Graph, Twitter cards and JSON-LD.
- Caching with outage fallback, and a signed webhook that clears the cache when content is published.
- Draft mode for the Storyblok Visual Editor.

| | |
|---|---|
| Backend | PHP 8.4.1+ (Sail runs 8.5), Laravel 13 |
| Frontend | Blade, Bootstrap 5 (Sass), Vite, no JavaScript framework |
| CMS | Storyblok (Content Delivery API, Management API through the CLI and generator) |
| Fonts | Inter and JetBrains Mono, self-hosted |
| Tests | PHPUnit against an in-memory Storyblok, Pint for style, GitHub Actions |

## Quick start

You need **Docker** and **make**. PHP and Node run inside the containers (Laravel Sail).

```bash
git clone <this repository> && cd storyblok-blog

make bootstrap   # installs Composer dependencies (creates ./vendor/bin/sail)
make start       # starts the containers
make setup       # .env, app key, migrations, npm install, asset build
```

Then open <http://localhost> and fill in the Storyblok values in `.env` (see below). Without them the pages cannot load
content. Run `make` to list every command, and `make dev` for Vite hot reload while you work on styles.

## Configuration

`make setup` creates `.env` from `.env.example`. The Storyblok keys:

| Key | Needed for | Notes |
|---|---|---|
| `STORYBLOK_SPACE_ID` | everything | Space settings, General |
| `STORYBLOK_DELIVERY_TOKEN` | reading published content | An access token of type *public* |
| `STORYBLOK_PREVIEW_TOKEN` | draft mode | An access token of type *preview* |
| `STORYBLOK_MANAGEMENT_TOKEN` | `make storyblok-generate` | Personal access token. **Never deploy it.** |
| `STORYBLOK_CLI_TOKEN` | `make storyblok-login` and the push targets | Personal access token with `users:read` and write access to components and datasources |
| `STORYBLOK_WEBHOOK_SECRET` | the webhook | The secret set on the Storyblok webhook. While empty, the webhook endpoint refuses everything |
| `STORYBLOK_DEFAULT_VERSION` | preview environments | `published` (default) or `draft`. Use `draft` only on a private preview site |
| `STORYBLOK_CACHE_FRESH_FOR` | caching | Seconds a read is served without asking Storyblok (default 300) |
| `STORYBLOK_CACHE_KEEP_STALE_FOR` | caching | Seconds an old copy is kept for outages (default 86400) |
| `STORYBLOK_EDITOR_ORIGINS` | draft mode | Origins allowed to frame draft pages (default `https://app.storyblok.com`) |

The space is assumed to be in the **EU** region. For another region set `STORYBLOK_MANAGEMENT_BASE_URI` and
`STORYBLOK_CONTENT_BASE_URI` (see the package's *Configuration* page) and change `--region eu` in the Makefile's
`storyblok-login` target.

## Setting up a Storyblok space

The schema, the `tags` datasource and sample content live in this repo, so an empty space can be filled with three commands.

```bash
make storyblok-login        # logs the Storyblok CLI in (its own HOME: your global CLI login is untouched)
make storyblok-push         # components: post, author, category, blog_index, page, site_settings, ...
make storyblok-datasources  # the "tags" datasource
make storyblok-stories      # sample author, categories, posts, home, about and settings
make storyblok-generate     # regenerates the transfer classes from the space
```

The Storyblok CLI looks for `storyblok/components/<space-id>/` and `storyblok/datasources/<space-id>/`. The directories
here are named after the original space, so **for your own space rename them** (`git mv storyblok/components/340703
storyblok/components/<your-space-id>`, same for `datasources`).

Run `make storyblok-generate` after every schema change and commit the result. The generator deletes every
`*Transfer.php` in `app/Storyblok/Transfers/`, so nothing hand-written lives there. Never use a digit after an
underscore in a field name (`headline_2` is skipped, use `headline_two`).

### In Storyblok

1. **Webhook** (Settings, Webhooks): point it at `https://<your-domain>/webhooks/storyblok`, tick the story and
   datasource events, set a secret and put the same value in `STORYBLOK_WEBHOOK_SECRET`.
2. **Visual Editor** (Settings, Visual Editor): set the preview location to your site's HTTPS URL, and set the
   "Preview path" of `site_settings`, `blog_index` and `author` to `/` (they have no page of their own).

## How it works

```
request ──> DetectDraftMode ──> controller ──> Blog ──> StoryblokContent ──> cache ──> Storyblok API
                                                 │
                                                 └──> RichtextRenderer, CodeHighlighter ──> Blade
```

| Where | What |
|---|---|
| `app/Blog/Blog.php` | Reads stories through the package and shapes them for the views (home, post, category, about, feed, sitemap) |
| `app/Blog/RichtextRenderer.php` | Richtext to safe HTML, heading anchors, the index and the word count; embedded blocks render through `components/blocks/*` |
| `app/Blog/CodeHighlighter.php` | Server-side highlighting with both themes' colors (Phiki) |
| `app/Blog/SeoMeta.php` | Titles, descriptions, canonical URLs, social cards, JSON-LD |
| `app/Blog/DraftMode.php`, `app/Http/Middleware/DetectDraftMode.php` | Visual Editor access: signed token, short-lived cookie, `noindex` and `no-store` |
| `app/Providers/AppServiceProvider.php` | Wires the Storyblok client: preview or delivery token, cache store, logger |
| `app/Storyblok/Transfers/` | Generated classes. Do not edit |
| `storyblok/` | Schema, datasource and sample stories, pushed with the CLI |
| `resources/scss/app.scss` | Design tokens as CSS variables for both themes, on top of Bootstrap |
| `resources/phiki/` | The highlighter's color themes (they must match the stylesheet; a test checks this) |

**Caching.** Published reads are cached for five minutes in a dedicated `storyblok` file store, and an old copy is served
for up to a day if Storyblok fails (a warning is logged). Drafts are never cached. The package can only clear its
whole cache, so a webhook empties that store. `make storyblok-clear-cache` does the same by hand.

**Draft mode.** The Visual Editor adds `_storyblok_tk[...]` to the URL: a SHA-1 of the space id, the preview token and a
timestamp, valid for an hour. A valid one switches the request to draft content with the preview token and sets a cookie
so links followed inside the preview stay in draft mode. Draft responses are `no-store`, `noindex` and can only be framed
by the Storyblok editor. The feed, sitemap and webhook never use draft mode. `/preview/exit` clears the cookie.

## Development

| Command | |
|---|---|
| `make test` | Run the test suite (`make test-filter F=SeoTest` for one) |
| `make lint` / `make lint-fix` | Check or fix the code style (Pint) |
| `make dev` | Vite dev server with hot reload |
| `make build` | Production assets (the tests need them: the layout uses `@vite`) |
| `make shell` | A shell inside the app container |

Tests never touch Storyblok. They run the real Storyblok client and cache on top of an in-memory Content Delivery API
built from `storyblok/stories/stories.json` (`tests/Support/`). `phpunit.xml` supplies placeholder credentials.

**CI.** GitHub Actions runs Pint, `composer validate --strict` and the tests on PHP 8.4 and 8.5 for every pull request
and push to `main`. A weekly workflow audits Composer and npm dependencies, and Dependabot keeps dependencies and the
pinned actions current. Workflow actions are pinned to commit SHAs.

Conventions are in [`CLAUDE.md`](CLAUDE.md): branches (never commit to `main`), Conventional Commits, `FRICTION.md` entries
for package problems, and "ask before adding dependencies".

## Going to production

- Set `APP_ENV=production`, `APP_DEBUG=false` and a real `APP_KEY`. `robots.txt` only allows crawling in production;
  every other environment tells crawlers to stay away.
- Use the **public** delivery token. Keep `STORYBLOK_DEFAULT_VERSION=published`. Do not deploy the management or CLI tokens.
- Build assets (`npm ci && npm run build`) and run `php artisan optimize` (caches config, routes and views).
- Configure trusted proxies: the sitemap, feed, canonical URLs and `robots.txt` use the host of the request.
- Serve over HTTPS (the Visual Editor needs it; the draft cookie is `SameSite=None; Secure`).
- Set the webhook secret, or content changes take up to five minutes to appear.
